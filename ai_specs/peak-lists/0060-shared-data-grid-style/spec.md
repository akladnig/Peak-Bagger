title: Shared Data Grid Style

## Problem

The Peak List details table has a distinct, theme-aware visual treatment, while `PeakMultiSelectResultsList`, the map `Search popup`, and ObjectBox Admin data grids each implement separate row padding, selection, hover, header, and divider styling. This produces inconsistent data-browsing surfaces and leaves ObjectBox Admin selected rows tied directly to the app seed colour rather than the Peak List details treatment. [L1] [L3] [L4]

## Proposed Outcome

Introduce a reusable, theme-derived Data grid style that gives the Peak List details table, peak multi-select results, Search popup results, and generic ObjectBox Admin grids one consistent desktop visual treatment without changing their existing data, navigation, selection semantics, controls, grouping, or scrolling models. [L1] [L2] [L3] [L5] [L6]

## User Stories

1. As a peak-list user, I see selected and hovered peak-detail and peak-search rows use the same visual language, so related peak-browsing surfaces feel consistent. [L1] [L3] [L4]
2. As a map user, I see Search popup result rows use the shared Data grid style while retaining result icons, grouping, metadata, and pagination. [L1] [L3]
3. As an administrator, I see every ObjectBox Admin entity grid use the same headers, spacing, hover feedback, and selected-row treatment as other data grids. [L1] [L3] [L4]
4. As a user of a customised app theme, I see Data grid style adapt automatically to the active light/dark colour scheme and seed colour without configuring a second setting. [L6]

## Requirements

1. Define and use the canonical term `Data grid style` for the shared presentation treatment of tabular and row-based data-browsing surfaces. It includes header and row spacing, typography hierarchy, dividers, hover feedback, and selected-row decoration; it does not require every participating surface to be structurally implemented as a Flutter table. [L2]
2. Retain the existing Peak List details table as the visual reference. Its card/surface framing, header hierarchy, cell and row spacing, clickable sortable headers, hover feedback, and selected-row decoration become the shared Data grid style baseline. Adjacent-data-row dividers are an intentional new Data grid style rule for every participating surface. Apply that style to both the Peak List summary rows (`_SummaryRowCard`) and details rows (`_PeakDetailsTableCard` / `_PeakDetailsTableRow`). Keep their existing measured column widths, labels, sort behavior, ratings, data formatting, selection, and deletion behavior local to their respective tables. [L3]
3. Apply Data grid style to `PeakMultiSelectResultsList` while retaining its checkbox, peak-name, elevation, and map columns; existing selection limit; disabled read-only selection; lazy vertical list; and absence of a header row. Replace the current green selected-row background with the shared selected-row decoration. Keep the checked checkbox indicator green so it continues to communicate checkbox state. [L1] [L3] [L4]
4. Apply Data grid style to `MapSearchResultsList`, the map `Search popup` results list. Retain entity-type icons, title/subtitle content, trailing metadata, group headers, loading-more row, no-result states, result keys, result tap behavior, and pagination. Search popup results must receive shared row spacing, dividers, typography hierarchy, hover feedback, and `DataGridTheme` pressed-row feedback, but must not gain a persistent local selected-row state. Render a shared divider only between two adjacent result rows, whether ungrouped or within one group. Do not render a divider between a group header and its first result, between a final result and the next group header or loading-more row, or around empty/minimum-query/no-results states. [L1] [L3] [L4]
5. Apply Data grid style to all ObjectBox Admin entity tables through `ObjectBoxAdminDataGrid`, `ObjectBoxAdminDataHeaderRow`, `ObjectBoxAdminDataRowTile`, and `ObjectBoxAdminCell`. Retain each entity's fields, primary-column rules, sorting, deletion controls, loading-more row, and linked horizontal/vertical scrolling. Replace the direct `seedColour` selected-row highlight, including the separate primary-cell colour, with the shared selected-row decoration. [L1] [L3] [L4]
6. Persistent selection across Peak List summary and details rows, peak multi-select results, and ObjectBox Admin must use the same theme-aware selected-row background and subtle top/bottom borders. Resolve row states in this order: selected, pressed, hovered, default. A hovered or pressed selected row must retain its selected treatment. Unselected interactive rows use shared hover feedback; Search popup rows use hover and pressed feedback only. Use the shared divider between adjacent data rows on every participating surface. Keep group headers and loading rows structurally distinct without adding dividers solely around them. [L4]
7. Preserve existing desktop scroll models and interactive affordances. Wide Peak List details and ObjectBox Admin grids remain horizontally scrollable; peak multi-select and Search popup remain vertically scrolling lists. The minimum supported desktop viewport is `1280 x 800`. At that viewport's default scale and `TextScaler.linear(2.0)`, preserve the existing wrapping, ellipsis, and horizontal-scroll behavior without introducing render overflow, overlap, or clipping beyond existing explicit `maxLines` and `TextOverflow` policies. Do not reduce existing interactive target geometry, keyboard activation, or semantic labels for sortable headers, row selection, checkboxes, result taps, and delete controls. Do not add a compact or mobile-specific layout. [L5]
8. Do not change user-visible labels, result ordering, filtering, pagination, selection limits, persistence, navigation, deletion confirmation, error/empty/loading behavior, or networking. This synchronous presentation change adds no new controllers, streams, timers, settings, persistence, APIs, secrets, or external-service calls. [L3] [L5] [L6]

## Technical Decisions

1. Add a `DataGridTheme` `ThemeExtension` in `lib/theme.dart`. It must expose `headerPadding`, `rowPadding`, `columnGap`, `headerTextStyle`, `rowTextStyle`, `dividerColor`, `dividerThickness`, `hoverColor`, `hoveredTextColor`, `pressedRowColor`, `selectedRowColor`, and `selectedRowBorderColor`. Provide `copyWith` and `lerp` consistent with the existing theme extensions. [L2] [L6]
2. Derive both light and dark `DataGridTheme` values with `DataGridTheme.fromColorScheme(ColorScheme, TextTheme)` and register them in `MyTheme._createLightTheme` and `MyTheme._createDarkTheme`. Use `EdgeInsets.symmetric(vertical: 4)` for `headerPadding`, `EdgeInsets.symmetric(horizontal: 12, vertical: 6)` for `rowPadding`, `12` for `columnGap`, resolved `textTheme.labelLarge` for `headerTextStyle`, resolved `textTheme.bodyMedium` for `rowTextStyle`, `colorScheme.outlineVariant` for `dividerColor`, `1` for `dividerThickness`, `colorScheme.primaryContainer.withValues(alpha: 0.5)` for `hoverColor`, `colorScheme.onSurface` for `hoveredTextColor`, `colorScheme.primary.withValues(alpha: 0.12)` for `pressedRowColor`, `darken(colorScheme.primaryContainer, 0.30)` for `selectedRowColor`, and `darken(colorScheme.primaryContainer, 0.08)` for `selectedRowBorderColor`. `headerTextStyle` is the complete shared header style and must be applied directly without a per-surface font-weight override. The extension must respond to the existing seed-colour, dynamic-scheme-variant, and contrast-level configuration without a new setting. [L6]
3. Refactor the Peak List summary and details rows to consume `DataGridTheme` rather than owning shared visual token values. Keep `RowHoverTheme` available for its existing non-grid consumers; do not broaden unrelated dashboard styling as part of this change. [L2] [L3]
4. Consume the extension directly in the existing row/list widgets rather than replacing their data structures or adding a global Flutter `DataTable` conversion. Apply `headerPadding` and `rowPadding` once around each logical header or row, not repeatedly within every ObjectBox cell. Use `columnGap` between every visual column boundary: Peak List columns; peak multi-select checkbox, peak-name, elevation, and map columns; Search popup icon, title/subtitle content, and trailing metadata; and ObjectBox Admin primary, scrollable data, action, and individual scrollable-cell columns. Preserve existing defined column widths; ObjectBox Admin's scrollable extent may grow by the inserted gaps. The Search popup may remain a `ListView` of result rows, and ObjectBox Admin may retain its current linked scroll-controller architecture. [L1] [L3] [L5]
5. Reuse existing widget harnesses, in-memory repositories, and `MaterialApp`/theme test wrapping. This change needs no new provider, persistence, service, network, or lifecycle Test Seam. [L7]

## Testing Strategy

Use vertical-slice TDD for the theme extension and each consumer's visual contract.

1. Extend `test/theme_test.dart` to verify that light and dark `MyTheme` instances install `DataGridTheme` and use every specified token formula from the resolved `ColorScheme` and `TextTheme`, including a non-default seed configuration. [L6] [L7]
2. Extend Peak List summary and details widget coverage to assert that selected and hovered rows consume the shared Data grid style; a selected row retains its selected background and borders while hovered; sortable details headers retain their existing behavior and accessibility; and representative headers and rows preserve their layout at `TextScaler.linear(2.0)`. [L3] [L4] [L5] [L7]
3. Extend `test/widget/peak_multi_select_results_list_test.dart` with a `MyTheme` harness to assert that selected rows use the shared decoration and retain it while hovered, while checked checkbox colour, read-only disabled selection, selection limits, keys, lazy-list behavior, and representative long-name layout at `TextScaler.linear(2.0)` remain unchanged. [L1] [L3] [L4] [L5] [L7]
4. Add or extend Search popup result-list widget coverage for shared row spacing, typography, divider, hover, and `DataGridTheme` pressed treatment while preserving group headers, entity icons, metadata, keys, empty/loading states, and tap callbacks without persistent row selection. Cover the approved divider placements for grouped, ungrouped, and loading-more results, and representative title/subtitle/trailing-metadata layout at `TextScaler.linear(2.0)`. [L1] [L3] [L4] [L5] [L7]
5. Extend ObjectBox Admin grid widget coverage to assert shared header/cell spacing, row dividers, hover treatment, and selected-row decoration across the generic grid while preserving sorting, deletion, and linked scrolling. Assert that a selected row retains its shared selected decoration while hovered, and cover a fixed primary column and horizontally scrollable cells at `TextScaler.linear(2.0)`. [L1] [L3] [L4] [L5] [L7]
6. Run targeted widget tests, `flutter analyze`, and the full `flutter test` suite. Preserve existing interaction tests. For every updated surface, widget coverage must pump the `1280 x 800` viewport with `TextScaler.linear(2.0)` and assert that no framework exception is reported. Assert the existing semantic labels and keyboard activation for sortable headers, selectable rows, checkboxes, Search popup result taps, and delete controls. Do not add robot tests because navigation and user journeys do not change. [L7]

## Out of Scope

1. Changing the structure, columns, labels, sort/filter behavior, result grouping, pagination, checkbox behavior, navigation, persistence, deletion flow, or loading/empty/error behavior of any participating surface. [L3]
2. Introducing mobile layouts, a compact table variant, new theme settings, a DataTable migration, additional state management, or new external dependencies. [L5] [L6]
3. Applying Data grid style to unrelated dashboard cards or non-data-grid controls solely because they currently use `RowHoverTheme`. [L3]
