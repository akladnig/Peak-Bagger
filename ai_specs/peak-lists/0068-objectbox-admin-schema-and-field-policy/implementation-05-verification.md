# Work Item 05 verification

Date: 2026-10-20. Scope: [Work Item 05](work-items/05-cancel-save-and-retained-shell-navigation-locks.md), ADS-1.0 amendment 2026-10-19, Desktop wide.

## Implementation

- All five existing hand-built editors use the same wrapping, right-aligned **FilledButton Cancel / Save** footer, inheriting the central primaryContainer/onPrimaryContainer pairing. Existing selectors, Calculate/domain actions, validators and service/repository persistence boundaries remain in place.
- Existing-record Cancel restores controllers/scalars from the committed record and returns to the same read-only details without submitting. Peak/Contact create Cancel delegates to their existing close boundary and abandons creation. Header Close still clears details. No confirmation, extra editor/create flow, dismissal binding or cross-destination draft retention was added.
- Local action guards read current mounted/editing/saving state, not a captured build-time flag. Duplicate Save, Cancel, Close, coordinate/source/boolean actions and view-on-map callbacks cannot bypass pending Save through callbacks retained before a rebuild. Recoverable/throwing Save retains its single draft; unexpected callback failures are logged and offer retry/cancellation. Contact now displays its returned save error rather than silently retaining the draft.
- `objectboxAdminSaveProvider` owns the routed Save lifetime, acquired before invoking the existing save callback (including awaited conflict checks/preparation, persistence, refresh and existing outcome feedback), released in `finally`. It survives successful refresh/create-pane replacement. Its live presentation scope keeps replacement panes' Edit/Close disabled until completion too, including while a newly created Peak's success dialog awaits acknowledgement. The browser notifier rejects input/selection/mode/search/sort/ordinary refresh during that lifetime. The Save-owned refresh retains the selected pane during its read rather than exposing an unlocked replacement while awaiting completion. Controls/rows/Delete show disabled semantics; the provider/action gates also reject stale callbacks.
- Shell destination actions read the same gate before pre-navigation cleanup. GoRouter `onEnter` hard-stops parsed departure without a deferred continuation; Admin `onExit` covers its route-exit/back fallback. A synchronous route `PopEntry` subscribes to the gate, covering system back before a widget rebuild as well as afterward. The app's small GoRouter subclass guards imperative `pop`, because popping a whole shell match can bypass a leaf route's onExit. It also rejects go/push/restore/replace/pushReplacement immediately at invocation (named variants dispatch through these methods), so a request made during Save cannot wait for Save to finish and then succeed at parsing. Blocked push futures complete without navigation; no rejected continuation is retained. These checks use the effective top-route state (including pushed routes), not just the base configuration URI. Existing outcome dialogs retain their local Navigator dismissal boundary. Other destinations' guards and navigation semantics are not replaced. An allowed idle departure explicitly clears creation/selection on the retained Admin screen, disposing its draft even though the shell branch remains mounted. Existing canonical selection/external entry and re-entry refresh remain intact.
- Existing Admin has no Escape/Ctrl+C panel-dismiss binding; none was added. Ordinary text editing and Cmd+C remain available. Keyboard shell activation uses its existing destination action, with the same pending gate.
