# Work Item 03 verification

Date: 2026-10-20. Scope: [Work Item 03](work-items/03-selectable-five-line-detail-values.md), ADS-1.0 amendment 2026-10-19, Desktop wide.

## Implementation and detail-path audit

- `lib/widgets/objectbox_admin_read_only_value.dart` owns the reusable semantic-labelled value viewport. A `TextPainter` uses the current value/style, wrapping width, locale, direction and actual text scaler. The viewport is the smaller of the complete text height and the first five rendered line metrics; empty/short content keeps its natural height. Measurement is recalculated on constraint/theme/scale changes and the temporary painter is disposed immediately.
- Complete `Text` content sits in a non-primary `SingleChildScrollView`, with its own scrollbar/controller. A `SelectionArea` owns framework-managed read-only selection. There is no `TextField`, `TextFormField`, app-owned display `TextEditingController`, input connection or text-mutation action. Text cursor, normal focus traversal, visible two-pixel primary focus outline and macOS copy remain available.
- Audited every detail implementation: the generic pane (including Track and maintenance entities), Peak, Route, PeakList, Natural Feature and Contact. All text/scalar values now share the viewport, not a field-name allowlist; Contact no longer bypasses the shared helper. Existing boolean values retain the disabled labelled checkbox and checked semantics.
- Record names displayed only in headers also use the shared viewport with their existing title style. This prevents very long names (including Contact's composed name) from pushing Close/Edit out of the panel, without truncating the name or changing title formatting. Existing visible labels, scalar/coordinate/colour/date/duration formatters and missing-value presentation remain unchanged.
- Every call site supplies record identity; viewport keys combine entity, record and field (or header identity). Scroll positions do not use PageStorage or an outer primary controller. Each mounted value disposes its owned focus/scroll resources; framework selection disposal stays with `SelectionArea`. Resizing retains the same value state and selection. Existing shell re-entry refresh/selection semantics are unchanged.
- Existing Route geometry/PeakList membership displays in forms already called the shared details helper and inherit its viewport, now with record identity. This is not the Work Item 04 form conversion: disabled read-only form fields, policy-driven eligibility and editable multiline controls remain separately scoped. No new editable field or save/cancel/navigation capability is introduced.
