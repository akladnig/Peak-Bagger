## Problem

Dashboard users can review distance, elevation, and bagged peaks over calendar periods but have no equivalent view of recorded Total Time and Moving Time. The existing chart cards are not fully consistent, so copying their behavior indiscriminately would reproduce that inconsistency. Time needs an explicit Distance-based reference, three clearly named chart views, and duration formatting suitable for totals measured in days. [L1] [L3] [L6]

## Proposed Outcome

Add a **Time** card to the existing Dashboard. Derive two series from eligible completed Tracks: Total Time in the theme-derived primary chart colour and Moving Time in the established secondary green. Reuse Distance's current calendar browsing and primary-series summary behavior, while giving Time its own stacked/line/clustered chart-type menu and a remembered startup choice. Time's header summaries wrap without shrinking text, and preference warnings survive navigation until they can be presented. Dashboard-wide Tab traversal uses one focus stop per card, reaches off-screen cards, and wraps at both ends. Explicit shortcuts provide the enumerated card actions, shell-destination navigation, Time preference Retry, and reordering; other shell actions intentionally have no keyboard entry path under L16. Failed card-order saves retain the visible order and offer Retry for the latest order. Other cards retain their chart controls, data, chart/header presentation, and chart preferences. Shortcut discovery, editable shortcuts, and a Help screen are deferred. [L1]–[L18]

## User Stories

1. As a Dashboard user, I can compare recorded Total Time and Moving Time over the same calendar periods used by Distance.
2. As a Dashboard user, I can inspect time as a subset-aware stacked column, two lines, or two side-by-side columns without losing my selected period or page.
3. As a returning user, I can reopen the app with my last successfully saved Time chart type selected and recover visibly if the preference cannot be loaded or saved.
4. As a Dashboard user, I can read day-scale time totals, period averages, and bucket details based on the same valid set of completed walks.
5. As a keyboard user, I can move between all Dashboard cards with Tab/Shift+Tab, including off-screen cards, and inspect Time's buckets, browse its calendar pages, and choose its period/chart type without tabbing through every internal control. [L11] [L14] [L15]
6. As a keyboard user, I can operate existing cards, open their linked map content, reach shell destinations, retry a visible Time preference warning, and reorder cards while retaining card-only Tab traversal. [L13]
7. As a Dashboard user, I can retain my visible card order after a failed save and retry saving the latest order. [L17]

## Requirements

### Card integration and reference behavior

1. Add a card with visible title exactly **`Time`** and stable card ID `time` to the existing Dashboard. Use its normal card chrome, grid, drag handle, reorder mechanism, and stored card ordering; introduce no separate Dashboard route or navigation destination. As a supporting placement default, insert Time after Distance in the default order; when an existing saved order lacks Time, append Time without rearranging existing cards. [L1] [L3]
2. Use **Distance** as the feature reference for loading, calendar selection, navigation, primary-series header reporting, hover/pinned inspection, and refresh behavior, except for the explicit Time-specific differences in this Spec. The current calendar contracts are those in Specs [0064](../0064-dashboard-calendar-navigation-and-local-walk-date/spec.md) and [0065](../0065-dashboard-weekly-tooltip-and-year-navigation/spec.md), with 0065 taking precedence for Year to Date browsing and tooltip text. Do not reintroduce historical rolling/half-window navigation or fixed-current-year-only Year to Date. [L3]
3. Retain Dashboard entry/exit, route/back behavior, existing Track-load failures and recovery, and unrelated offline/slow-network behavior. This card performs no runtime network calls. Track-data loading shows the existing loading presentation, without flashing `No time data yet` or stale header values. [L1] [L3] [L8]

### Time meanings, eligibility, and aggregation

4. Use existing `GpxTrack.totalTimeMillis` for **`Total Time`** and `GpxTrack.movingTime` for **`Moving Time`**; both are milliseconds. Total Time includes recorded resting time within recording segments but excludes inter-segment recording gaps (`Paused Time`). Moving Time excludes resting time. Do not recalculate time from GPX, replace Total Time with end-minus-start elapsed time, or add paused time. A Track with four hours moving, one hour resting, and a thirty-minute recording gap contributes five hours total and four hours moving. [L2]
5. Qualify a Track only if both durations exist and satisfy **`0 ≤ Moving Time ≤ Total Time`**. Both series, their buckets, endpoint selection, totals, and averages use this same Track set. Keep valid zero-duration Tracks, including a zero/zero Track. Exclude missing, negative, or inconsistent duration pairs from this card without mutating or repairing their stored records. [L8]
6. Also apply the existing calendar eligibility: decode the Track's calendar-only date through the established Track-date boundary; exclude unknown dates and dates after Dashboard's Mac-local reference calendar day. Assign the entire Track duration to its Track-date bucket, as Distance assigns its metric; do not split a multi-day Track across dates or convert a duration using timezone/DST rules. Use both series' identical selected-page and bucket boundaries. [L2] [L3] [L8]
7. Sum full-precision durations before formatting. Empty buckets within navigable history are zero-valued; distinguish them from having no eligible Tracks at all. If no Tracks qualify after duration/date validation and the reference-day cutoff, show exactly **`No time data yet`** and clear header summaries. Zero/zero eligible history still renders a chart and navigation rather than the wholly-empty message. [L8]

### Periods, navigation, and summaries

8. Retain the exact preset order **`Week`, `Month`, `Last 3 Months`, `Last 6 Months`, `Last 12 Months`, `Year to Date`, `All Time`**, initially selecting **`Last 12 Months`** and its current page. A different preset opens its current page, independently of the selected chart type. Do not persist the preset/page as part of remembering the chart type. [L3] [L5]
9. Preserve the reference page/bucket contracts: Monday–Sunday Week with daily buckets; complete calendar Month with daily buckets; current-month-anchored 3-/6-month pages with clipped Monday-based weekly buckets; 12-month pages with monthly buckets; Year to Date with twelve monthly positions and one-year historical steps; All Time with yearly buckets and up to twelve anchored years per page. Use complete calendar steps, not elapsed-day approximations. [L3]
10. Preserve **First → Previous → Next → Last**, with First/Last jumping to pages containing the earliest/latest eligible Time Track. Traverse empty intervening pages, bound backward navigation at the earliest eligible page and forward navigation at the current period, and enable each action according to its own destination. Button and horizontal/trackpad browsing must agree. Enabled endpoint tooltips/action names are exactly `First` and `Last`; arrows retain Distance's preset-specific text, including `Previous Year` and `Next Year`. Disabled buttons have no visual tooltip but retain meaningful accessible names, disabled styling, and the basic cursor. [L3]
11. Keep the reference toolbar on one row, substituting the Time chart-type menu button for the binary mode toggle. Preserve the visible date-range label and tooltip-date formats, including compact weekly tooltip titles for Last 3/6 Months and `Thu 15 Oct`-shaped Month titles. The overall date-range label retains its existing weekday-bearing format. [L3] [L5]
12. The header uses **Total Time only**, with `Total:` and the existing average labels: Week `Daily Avg:`, Month `Weekly Avg:`, Last 3/6/12 Months and Year to Date `Monthly Avg:`, All Time `Annual Avg:`. Reuse Distance's denominator rules, including zero periods, all twelve months for historical years, and elapsed months including the current month for the current Year to Date page. Header values, chart, and date range must describe the same selected page. Do not add a second Moving Time header summary. **Time's summary header wraps when its contents do not fit**, preserving full labels/values at the active text scale. Do not shrink the summaries with `FittedBox.scaleDown`, reduce text scale, or truncate essential values. This permission to wrap applies to the summary header, not the one-row toolbar in requirement 11; other cards retain their header presentation. Resolve any actual dependent Pending profile value before layout work requiring it. [L7] [L10]
13. Preserve independent per-card browsing and the reference refresh/rollover rules: retain an allowed historical page, clamp a page before newly shortened history, recalculate values/controls coherently, and clear obsolete inspection state. First/Last remain one-off jumps rather than following later imports. Reconcile the reference date on Dashboard activation, data refresh, or interaction through the existing clock; add no midnight timer. Preserve current-page following and historical-page remapping from 0064/0065. All three Time chart types follow these same rules. [L3] [L5]

Selecting a type closes the menu and preserves the selected preset/page; selecting the current type is a no-op. Escape or an outside click dismisses without changing the type. Keyboard opening, selection, dismissal, and focus return follow requirements 27–31, returning focus to the owning card after a keyboard-opened menu closes. Menu focus return follows requirement 28's inspection policy rather than restarting inspection unconditionally. Preserve pointer operation of the existing button. Do not use `Switch to column view` as the Time menu's stacked-choice label. [L3] [L5] [L11] [L15]

Moving Time uses `ChartSeriesTheme.secondarySeriesColor`, currently **`#2E7D32`**. Preserve the shared selected-colour and lightened tooltip-colour derivations, adapting to theme changes in light/dark modes. [L1]
17. **Stacked column view:** draw green from zero to the Moving Time bucket value, then the primary colour from Moving Time to Total Time. Full height is Total Time, never Total Time plus Moving Time. Five hours total/four moving renders four hours green plus one hour primary. A zero-height portion is omitted naturally, including no primary remainder when both totals are equal. Tooltip meanings remain the two original durations, not a renamed resting-time series. [L4]
18. **Line view:** draw Total Time and Moving Time on one duration axis using their respective colours; retain the shared hover/pin behavior and keep the green series visible when the lines coincide. **Clustered column view:** draw Total Time first/left and Moving Time second/right on a common zero-based axis, with their respective full values. Five hours total/four moving produces separate columns at five and four hours. [L1] [L3]
19. In every type, each inspected bucket shows its reference date title and two metric rows in this order: **`Total Time: <duration>`**, **`Moving Time: <duration>`**. Use the agreed duration formatting and corresponding theme-derived tooltip colours. Provide equivalent keyboard inspection under requirements 28–30 and expose the inspected date and both values to assistive technology. Changing type clears incompatible inspection presentation rather than leaving a stale tooltip, while retaining the selected calendar page. [L1] [L4] [L5] [L6] [L7] [L11]
20. Apply the new chart-type menu, stacked subset rendering, clustered choice, and remembered type **only to Time**. Shared implementation may gain opt-in capabilities, but Distance, Elevation, and Peaks Bagged retain their current mode controls, labels, defaults, data eligibility, chart/header presentation, and chart preferences. The approved Dashboard-wide focus traversal, dropdown keys, and keyboard access in requirements 27–37 are the explicit interaction-scope expansion, including visible focus/row selection and keyboard reordering, subject to L16's shell-access limitation. Requirement 38 additionally changes recovery for saves through the shared card-order mechanism. These changes do not authorise chart-type or chart-preference migration on the other cards. Their consistency migration is a separate follow-up. [L3] [L11] [L13] [L14] [L16] [L17]

### Duration display

21. Tooltip values and header totals/averages use **`xd yh zm`**, for example **`2d 5h 7m`**, with a duration day equal to **24 hours**. As formatting defaults, include all three unpadded components (`0d 0h 0m`, `0d 5h 0m`), carry hours/minutes into their normal ranges, and truncate only the final displayed value to whole minutes, preserving the existing whole-minute display convention. Do not truncate individual Tracks before summation or before calculating an average. [L6]
22. The Y-axis expresses duration in days, with no space before `d`, such as **`0d`**, **`2.5d`**, **`5d`**. Use compact decimal values, omitting unnecessary trailing zeroes. As an axis-supporting default, choose readable intervals/precision that keep distinct ticks distinguishable even for sub-day data; do not force every small tick to display `0d`. Chart scaling accounts for both series and the true stacked height; an all-zero chart remains renderable. This does not change Track details or other cards' display formatters. [L4] [L6]

### Remembered chart type, loading, failures, and retries

23. Persist Time's last selected chart type as a small preference and restore it on app startup, including after navigating away/back or reordering the card. With no saved preference, use **Stacked column view**. A missing or unsupported stored value safely falls back to stacked without affecting domain records or other cards. Restore the choice without first presenting another chart type as the completed startup state; preference loading has a visible pending presentation. [L5]
24. On startup preference-read failure, use Stacked column view and show a SnackBar with exactly **`Couldn’t load Time chart preference.`** and action **`Retry`**. Keep the chart usable. Retry repeats the read and applies a valid restored choice if the user has not since selected another type; a late read must not overwrite a newer explicit choice. [L9]
25. On selection, immediately show the selected chart type and save it. On save failure, retain that visible type and show a SnackBar with exactly **`Couldn’t save Time chart preference.`** and action **`Retry`**. The previous successfully saved type remains the startup default until another save succeeds. Treat a preference API's reported unsuccessful write as failure as well as thrown exceptions. Do not report persistence success before the write completes. [L5] [L9]
26. A save Retry writes the latest selected type, not an obsolete captured choice; coalesce/serialize writes so older completions cannot overwrite the latest intended preference. Deduplicate retries for the same pending operation and keep chart browsing available. Own preference failures and warning-delivery state at app scope, independently of Time's card lifecycle. Show the exact requirement 24/25 SnackBar immediately on an active Dashboard; if Dashboard is inactive or disposed, retain the unpresented warning and show it **once on the next active Dashboard**, even when Time is off-screen. Mark a warning as presented so rebuilds, card recreation, and later navigation do not replay it. Clear a queued warning when a later successful operation resolves that failure before presentation. Late loads, superseded saves, and disposal must not restore stale visible state or publish feedback to an inactive/disposed surface. Log technical failures with useful operation context without exposing raw exception text as user guidance. [L5] [L9] [L12]

### Dashboard card focus and keyboard interaction

27. While traversing Dashboard with **Tab / Shift+Tab**, use **one focus stop per Dashboard card** in the current displayed/stored card order: Tab moves to the next card and Shift+Tab to the previous card, with both able to enter/leave Time's chart through its owning card. Traverse the **entire stored order**, including off-screen cards not yet constructed by the lazy grid: bring the target into view and focus it after construction rather than skipping it. **Tab from the last card wraps to the first; Shift+Tab from the first wraps to the last.** Skip internal buttons, menus, chart buckets, and surrounding app navigation as Tab stops in this Dashboard traversal. This applies across Dashboard cards, not only Time. Each focused card has a meaningful accessible name and a visible focus indicator distinct from hover/inspection. Existing internal controls remain pointer-operable and have the explicit keyboard paths below; menus and shell navigation receive temporary focus rather than becoming extra card-traversal stops. [L11] [L13] [L14]
28. **When Time receives keyboard focus with a rendered chart**, start inspection on its selected page's latest bucket containing eligible Tracks, or the first bucket when the page has no eligible Tracks. Valid zero-duration Tracks count as activity for this choice. Loading and wholly-empty states have no bucket to inspect. **Left / h** inspect the previous bucket; **Right / l** inspect the next bucket. The first directional key after focus moves from the already-inspected initial bucket, including requirement 29's boundary behavior. Show the same date and both metric values as pointer inspection, including coincident series and zero-valued buckets. **Escape** clears inspection while leaving focus on Time's card; the next Left/Right/h/l initializes the initial bucket without also stepping. After **W/B** changes page, inspect the destination page's latest eligible bucket, or its first bucket if empty. Returning focus from a menu preserves a still-valid inspection; changing the period or chart type clears the old inspection, and the next directional key initializes it without also stepping. Menu focus return does not unconditionally restart inspection. Obsolete inspection after refresh/rollover still clears under requirement 13. [L11] [L15]
29. At the first/last bucket, Left/h or Right/l moves to the previous/next calendar page using the toolbar's page sequence and bounds. Land on the **last bucket of the previous page** or **first bucket of the next page**, respectively, including empty intervening pages. At the overall navigation limit, remain on the boundary bucket. Keep card focus and selected-page/header/chart/control agreement throughout; apply the existing refresh/rollover reconciliation and reject stale callbacks. [L11]
30. With Time's card focused, **W** invokes the toolbar's Next page action and **B** its Previous page action, using the same calendar steps, limits, and reconciliation. **P** opens Time's existing Period dropdown and **C** its Chart type dropdown. These are card-scoped letter-key shortcuts, not app-global commands; preserve normal editing/copy shortcuts and disable chart/page shortcuts while a dropdown owns keyboard interaction. Do not introduce a combined card-actions menu. [L11]
31. In Dashboard dropdown menus, **Down / j** select the next item and **Up / k** the previous item; **Enter** applies the highlighted choice. **Escape** dismisses without applying a new choice and restores focus to the owning card. Closing a keyboard-opened menu after selection likewise returns focus to that card. Tab/Shift+Tab dismiss an open dropdown and continue to the next/previous Dashboard card rather than traversing its items or internal controls. Retain the existing Period and chart-type choices, selected-item indication, and pointer behavior. The new three-choice Chart type menu remains Time-only; this does not add menus to other cards' binary mode controls. [L11]

### Keyboard access to existing Dashboard actions

32. With **Distance, Elevation, or Peaks Bagged** focused, **W/B** invoke that card's existing Next/Previous calendar-page actions, **P** opens its Period dropdown, and **C** directly activates its existing binary line/column toggle. Do not add a chart-type menu to those cards. With any of the **four timeline cards**, including Time, focused, **Home/End** invoke **First/Last**, using exactly the toolbar destinations, eligibility, limits, enabled states, and reconciliation. These shortcuts preserve each card's independent state and current chart-type defaults. [L13]
33. With **Latest Walk** focused, **B/W** invoke its existing **Previous track/Next track** actions, respecting their enabled states and retaining card focus while browsing. **Enter** opens the displayed Track through its existing map action. With the separate **My Year to Date** card focused, **B/W** invoke its existing **Previous year/Next year** actions, respecting that card's existing bounds; do not substitute the timeline Year to Date contract. [L13]
34. On initial focus of a populated **My Lists** or **My Ascents** card, select its first row; an empty card has no selected row to open. **Down/j** and **Up/k** select the next/previous row **without wrapping**, scrolling the selected row into view. **Enter** invokes the selected row's existing map action: the list action for My Lists and the Track action for My Ascents. **S** toggles My Ascents' existing date sort, retaining the selected row when possible. Rows remain outside Tab traversal. Make row selection and keyboard focus visibly distinct from hover, and preserve existing pointer actions and navigation outcomes. [L13]
35. **F6** from a Dashboard card temporarily focuses the currently selected shell destination. Within that temporary navigation scope, **Up/Down or k/j** highlight a destination and **Enter** activates it through the existing shell navigation action. **Escape/F6** returns to the previous Dashboard card without navigating. **Tab/Shift+Tab** returns to that card and resumes next/previous-card traversal under requirement 27. Shell destinations remain excluded from the normal Dashboard Tab sequence; temporary shell focus must not also dispatch card shortcuts. Keep this scope **destination-only**: add no keyboard entry path for Background Jobs, its panel controls, or other shell notification actions. Preserve their pointer operation. This intentionally narrows L13's earlier “every existing action” commitment and leaves the documented accessibility gap in Technical Decision 11; it does not add routes or a new navigation surface. [L13] [L16]
36. While a **Time preference warning SnackBar is visible**, **R** from **any focused Dashboard card** invokes that displayed warning's existing **Retry** action, even when Time is off-screen. Preserve focus on the current card, deduplicate pending retries, and retain requirements 24–26's read/save/latest-choice policy. Without a visible Time preference warning, R does nothing. The SnackBar action remains pointer-operable and introduces no extra Dashboard Tab stop. [L9] [L12] [L13]
37. With a Dashboard card focused, **Cmd+Shift+Left** moves it one position earlier and **Cmd+Shift+Right** one position later in stored card order. At either end, the unavailable move is a no-op, without wrapping. Retain focus on the moved card, bring it into view, and persist through the existing card-order mechanism. All card shortcuts in requirements 28–37 apply only within the active Dashboard/card context; only the owning dropdown or temporary shell scope handles its interaction keys. Preserve typing and normal modified editing/copy shortcuts, including Cmd+C; the two explicit Cmd+Shift reorder shortcuts apply only to focused cards. R likewise must not intercept typing or modified shortcuts. [L13] [L14]

### Card-order save recovery

38. For changed Dashboard card orders saved through the existing mechanism, including pointer and keyboard reordering, retain the new visible order if saving fails. Show a SnackBar identifying the card-order save failure with action exactly **`Retry`**; Retry saves the **latest visible order**, not the order captured by an earlier failed attempt. Keep the retained order authoritative for traversal and retain card focus. Treat thrown errors and a reported unsuccessful preference write as failures, log technical context separately, and do not claim persistence success before completion. The previously saved order remains the restart result until a later save succeeds. As supporting implementation defaults, serialize/coalesce order writes so stale completions cannot overwrite the latest intended order and deduplicate retries of the same pending save. Use the existing order storage rather than adding another preference. Retry remains pointer-operable and adds no Dashboard Tab stop or new keyboard entry path under L16; **R remains Time-preference-only** under requirement 36. [L16] [L17]

## Technical Decisions

1. Adopt **ADS-1.0** from project-root-relative [ai_specs/coding-rules.md](../../coding-rules.md) and the **Desktop wide only** profile in [ai_specs/app-profile.md](../../app-profile.md): macOS-only, wide desktop, maximised on launch, compact keyboard/pointer controls, semantic light/dark styling, visible focus, accessible labels, distinct selected/hover states, and respected text scaling. ObjectBox, Riverpod, and GoRouter remain mandatory. Technical Decision 11 records the intentional keyboard-access limitation and its unresolved standard alignment; no foundation replacement is proposed.
2. Use a thin Time metric/card adapter over `lib/services/summary_card_service.dart`, `lib/widgets/dashboard/summary_card.dart`, `lib/widgets/dashboard/summary_chart.dart`, and `summaryPageControllerProvider`. Filter the duration pair once consistently for both metrics and navigation. Domain records remain authoritative in the existing ObjectBox-backed Track flow; Time stores no derived analytics or domain entities. This feature needs no schema/model generation or time recalculation. [L2] [L3] [L8]
3. Preserve existing adapters' defaults through explicit opt-in chart-type/menu/subset-stack capabilities. The current internal `stacked` renderer draws its secondary segment from the primary value to the secondary value; it cannot directly represent a Moving Time secondary value smaller than Total Time. Add a deliberate Time-specific subset policy rather than globally reversing the shared renderer or mislabelling the remainder. The existing grouped-bar support is a useful implementation seam for clustered columns. [L3] [L4]
4. Riverpod owns the selected Time chart type, preference load/save/error state, warning identity/presentation state, and injected storage dependency. Use shared preferences separately from ObjectBox; stable persisted identifiers for the three types must not depend on enum indices or visible labels. Keep the preference and unpresented failures app-owned across card disposal; widgets render state and dispatch intents, and own only transient menu/focus/inspection presentation. An active Dashboard-level feedback owner presents/consumes warnings independently of whether the lazy grid has constructed Time, observing route activation and avoiding duplicate listeners/effects on remount. Reuse the established preference-loader/override pattern while adding controllable read/write failure seams where needed. Existing preference code that silently swallows failures is not sufficient for L9/L12. [L5] [L9] [L12]
5. Reuse the `ChartSeriesTheme` extension and shared colour helpers; do not duplicate the palette. Add reusable duration display helpers at the project's shared formatter boundary, such as `lib/core/number_formatters.dart`; do not import a screen merely to obtain its formatter or globally replace `map_screen_panels.dart`'s Track-details formatting. Keep numeric duration units explicit when adapting milliseconds to chart days. [L1] [L6]

Existing deterministic seams include explicit Track fixtures, `SummaryMetricDefinition`, `SummaryCardService` date/page inputs, `SummaryCard.now`, `DashboardScreen.now`, `dashboardReferenceClockProvider`, provider overrides, and `onVisibleSummaryChanged`. Menu/focus/controllers/listeners and scheduled feedback have explicit cleanup owners; a widget disappearing must not corrupt an app-owned pending preference write or discard an unpresented failure. Keep Time's initial focus, menu-return, and cleared-inspection transitions distinct under requirement 28. [L3] [L5] [L9] [L11] [L12] [L13] [L14] [L15]
7. Integrate Time's header update and preference-read completion into the existing Dashboard readiness/frame-accounting path where applicable: a default painted before a pending read resolves must not falsely count as restored local data. A visible fallback after a failed read remains a failed read outcome rather than fabricated persistence success. Preserve the current dashboard dependency reporting. This is integration with existing readiness semantics, not a new performance target. [L5] [L9]

Refinement decisions L10–L12 explicitly settle header wrapping, keyboard/focus/menu behavior, and warning delivery/latest-choice Retry.
