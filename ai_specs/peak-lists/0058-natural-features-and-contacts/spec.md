## Problem

Peak Bagger has no persisted collection for Tasmanian OpenStreetMap natural features and no independent Contact entity. Administrators cannot import, inspect, curate, or refresh natural geographic features from the supplied local export, nor can they maintain a simple address-book record through ObjectBox Admin. [L1] [L9]

## Proposed Outcome

Add a `NaturalFeature` ObjectBox entity, a deterministic local-source refresh flow, and a Peak-style ObjectBox Admin details pane. Add an independent `Contact` entity with its own ObjectBox Admin create, edit, search, and delete flow. The new Natural Feature collection remains separate from Peaks and is not added to map or peak-list behavior. [L1] [L7] [L8] [L9]

## User Stories

1. As an administrator, I can refresh Tasmanian named natural features from the configured local JSON file and see exactly how many were created, updated, protected, or skipped. [L3] [L5] [L6] [L7]
2. As an administrator, I can inspect and correct a Natural Feature while keeping its OSM identity immutable and retaining selected local curation across eligible OSM refreshes. [L2] [L5] [L6] [L8]
3. As an administrator, I can add, edit, search, and delete independent Contacts without creating relationships to Peaks, Tracks, Routes, or other current entities. [L9] [L10]
4. As an administrator, I can delete a stale Natural Feature knowing that a later source refresh will recreate it only when the source still contains its OSM identity. [L5] [L10]

## Requirements

1. Add a singular `NaturalFeature` ObjectBox entity, displayed as `Natural Features` in ObjectBox Admin. It must persist generated `id`, `name`, `altName`, `tag`, `country`, `county`, `region`, `latitude`, `longitude`, `gridZoneDesignator`, `mgrs100kId`, `easting`, `northing`, numeric `osmId`, `osmType`, and `sourceOfTruth`. [L1] [L2] [L4] [L6] [L8]
2. `NaturalFeature.id` is generated by ObjectBox. `osmType` is exactly `node`, `way`, or `relation`, and `osmId` is the numeric JSON `id`. The composite `(osmType, osmId)` is the sole OSM feature identity for matching source rows to stored records; do not treat `osmId` alone as unique or rewrite source IDs. Before opening the write transaction, reject the refresh when eligible candidates contain a duplicate identity or the stored Natural Feature collection contains duplicate identities. Either condition is a refresh failure, commits no changes, and reports no success counts. [L2]
3. Add an independent `Contact` ObjectBox entity, displayed as `Contacts` in ObjectBox Admin, with generated `id`, `firstName`, `surname`, and `nickname`. Do not add contact relations or expose Contacts in other app domains. [L9]
4. Add `Refresh Natural Features` immediately below `Refresh Peak Data` on macOS Settings. Its subtitle is `Import Tasmanian natural features from the local source file`; tapping starts the import immediately without a confirmation dialog. [L7]
5. Peak Bagger is a macOS-only application. This maintainer workflow reads the fixed local path `/Volumes/Services/Features/tasmania_natural_features.json`; do not add a source-file picker or configuration UI. The fixed path is supported only in an unsandboxed macOS maintainer build. A source element is any JSON element. A tag used by the importer must be a JSON string; a non-string tag or non-object `tags` value is absent. A candidate is a supported `node`, `way`, or `relation` with at least one non-empty trimmed `tags.name` or `tags.natural`; an eligible candidate has both required tags. Ignore a source element with neither required non-empty trimmed tag, including untagged geometry-dependency nodes and ways; it never becomes a Natural Feature or counts as a skip. A candidate with exactly one required tag, an unsupported-type source element with one or both required tags, or a candidate whose JSON `id` is absent, non-integer, non-positive, or outside the positive signed 64-bit ObjectBox range `1..9,223,372,036,854,775,807` is invalid and counts as a skip. Do not invent `Unknown` names or fallback tags for otherwise invalid source elements. If the source file is absent or unreadable, preserve all Natural Features and fail with `Error refreshing natural features: source file is unavailable at /Volumes/Services/Features/tasmania_natural_features.json`. [L3]
6. Resolve all geometry only from that local export. Do not request supplementary OSM geometry or make any network call. Every coordinate used for geometry must be a finite numeric WGS84 value with latitude in `[-90, 90]` and longitude in `[-180, 180]`. Calculate lengths, signed areas, and centroids in a fixed Tasmania-local equirectangular plane using WGS84 mean Earth radius `6,371,008.8 m`, reference latitude `-42.0` degrees, and reference longitude `146.0` degrees: `x = R * radians(longitude - 146.0) * cos(radians(-42.0))` and `y = R * radians(latitude + 42.0)`; convert the resulting coordinate back to WGS84 latitude/longitude. Use direct `lat`/`lon` for nodes; area centroids for closed ways; length-weighted line centroids for open ways; area-weighted outer-ring centroids with inner rings subtracted for multipolygon relations; and length-weighted centroids for other resolvable relations. Zero-length geometry and zero-area rings are invalid. A way used for geometry requires an ordered numeric `nodes` list, and a relation member used for geometry requires a valid `type` and numeric `ref`; missing or malformed values make that candidate's geometry unresolved, count as a skip, and do not fail the whole refresh. For relations, resolve only direct `way` members: do not recurse through relation members and ignore node members. For a multipolygon, accept only `outer` and `inner` direct-way member roles; any blank or other role makes the relation invalid. Join contiguous way-node sequences into rings, reversing member sequences where necessary; use relation-member order as the deterministic tie-breaker when more than one segment can attach. Every outer and inner ring must close, and every inner ring must be strictly contained by exactly one outer ring; an inner ring that touches or crosses an outer boundary is invalid, skips the relation, and logs the geometry error through an injectable diagnostic seam. Combine multiple outer rings by absolute area and subtract inner-ring absolute areas, regardless of ring winding. For a non-multipolygon relation, use every resolvable direct way-member segment in the length-weighted centroid; skip it when none resolve. Skip an element if required geometry is missing, disconnected, invalid under these rules, or produces no finite centroid. [L3]
7. Derive `gridZoneDesignator`, `mgrs100kId`, `easting`, and `northing` from each imported or recalculated latitude/longitude using the same MGRS conversion behavior as Peaks. `gridZoneDesignator` remains read-only. An MGRS-only edit parses components with the record's currently stored derived grid zone and cannot change zones; changing the derived grid zone requires latitude/longitude input, which then recalculates all MGRS fields. A failed MGRS conversion skips that source element. [L3] [L8]
8. Map source fields as follows: `name` comes from `tags.name`; initial `altName` comes only from `tags.alt_name`; `country` initially is `Australia`; `region` initially is `Tasmania`; `county` initially is empty; latitude and longitude are the derived representative coordinate; and `sourceOfTruth` initially is `OSM`. Trim text values. A non-string `alt_name` is absent. Do not infer county or use alternate-name tags other than `alt_name`. [L4] [L6]
9. Store `tag` as the trimmed `tags.natural` value except when `tags.natural == 'water'`: use a non-empty trimmed string `tags.water` value, such as `lake` for `water=lake`; otherwise store `water`. Treat a non-string `tags.water` value as absent. Never include the literal `water=` prefix. [L4]
10. Trim all editable Natural Feature text fields on save. `name` and `tag` must remain non-empty, and `sourceOfTruth` must be exactly `OSM` or `Manual`. An `altName` must not equal `name` after trimming and case-insensitive comparison. A rejected value keeps the edit form open with the existing inline-validation behavior. [L4] [L8]
11. Refresh is an atomic upsert. After duplicate-identity validation, for a matching eligible OSM identity, retain the generated ObjectBox `id`, update source-derived values, and insert a new row for an unmatched source identity. Retain stored Natural Features that are omitted from a subsequent source file. Element-specific geometry and MGRS failures are counted as skips; duplicate-identity validation, file reading, JSON parsing, or persistence failure commits no partial refresh changes. [L2] [L5]
12. Only a Natural Feature with `sourceOfTruth == 'OSM'` is eligible for source refresh. The details pane must let an administrator set `sourceOfTruth` to exactly `OSM` or `Manual`; changing it back to `OSM` restores eligibility on the next refresh. A matching `Manual` row is protected and must not be changed by refresh. [L6] [L7] [L8]
13. For eligible OSM records, refresh preserves `altName`, `country`, `county`, and `region`. It also preserves the stored `name` when the stored `altName` is non-empty. Refresh replaces all other source-derived data, including `tag`, coordinates, and MGRS fields. [L5] [L6]
14. Immediately hand the refresh to the existing in-app `Background job` notification flow using an import-classified `refreshNaturalFeatures` job kind. If interrupted by app closure, recover it with exactly `Natural feature refresh cancelled when app was closed`. While it runs, show its progress indicator, disable competing Settings maintenance actions through the existing busy-state behavior, and disable every Natural Feature mutation action, including Save on an already open form and delete; preserve the existing Background job contract without adding OS-level background execution or user cancellation. If another Background job is already running, do not start the refresh, retain the existing already-running feedback, and leave persisted Natural Features unchanged. On success, show exactly `Natural features refreshed: {created} created, {updated} updated, {protected} protected, {skipped} skipped.` Classify source elements in this order: ignore elements with neither required tag; count invalid candidates as skipped; count an otherwise eligible OSM feature identity that matches a Manual row as protected before attempting geometry or MGRS conversion; then count any remaining eligible candidate with unresolved/invalid geometry or MGRS-conversion failure as skipped. Created and updated count only successfully persisted eligible OSM records. Do not count stored source omissions in these totals. On failure, show an error dialog and a status beginning `Error refreshing natural features:`. [L3] [L7]
15. Add a dedicated Natural Feature details pane, form, and save path modeled on Peak coordinate editing. It must show the selected `name` as the title, falling back to `{osmType} {osmId}` only when no name is available. All fields except `id`, `osmType`, `osmId`, and the derived `gridZoneDesignator` are editable. Show `gridZoneDesignator` as read-only and recalculate it from the selected latitude/longitude or MGRS input. Latitude/longitude and MGRS editing, validation, calculation, save, cancellation, and persistence-failure behavior must otherwise match the existing Peak interaction pattern, except that the Natural Feature form must validate and persist only `OSM` or `Manual` source-of-truth values and must not apply Peak/HWC provenance semantics. Do not provide an `Add Natural Feature` button. [L8]
16. Add a confirmed ObjectBox Admin delete action for Natural Features. Deleting any Natural Feature removes the local row. If the source later contains that OSM identity, the next refresh recreates it with `sourceOfTruth = OSM`, regardless of the deleted row's prior source of truth. Do not add tombstone or suppression storage. [L10]
17. Natural Feature search is case-insensitive across `name`, `altName`, `tag`, `osmType`, and decimal `osmId`; it must not search country, county, region, coordinates, MGRS fields, or source of truth. Retain the current ID-based ascending/descending table sort behavior. [L10]
18. Show `Add Contact` only while `Contacts` is selected in ObjectBox Admin. A new Contact opens in edit mode with blank fields. Trim all text inputs; saving requires at least one non-empty `firstName`, `surname`, or `nickname`. Blank records must not persist, but duplicate names and nicknames are valid. Cancelling discards unsaved changes; saving selects the persisted row and retains its generated ID. [L9]
19. Contact display name is the trimmed `{firstName} {surname}` with blank parts omitted; if both name parts are blank, it is the non-empty nickname. Use `New Contact` only during initial creation before the record is valid. Show `firstName`, `surname`, and `nickname` as distinct table columns, search case-insensitively across all three fields, and retain ID-based sort behavior. [L9] [L10]
20. Add a confirmed ObjectBox Admin delete action for Contacts. It permanently removes the selected Contact. [L10]

## Technical Decisions

1. Keep the terms `Natural Feature`, `OSM feature identity`, `Natural Feature source of truth`, and `Contact` aligned with `GLOSSARY.md`. `NaturalFeature` is singular in Dart/ObjectBox while the admin collection label is plural. [L1] [L2] [L6] [L9]
2. Parse the local Overpass JSON into an index of nodes and ways before materializing eligible tagged features so ways and relations can resolve their geometry regardless of export order. Read source text through an injectable file-reading seam on the app isolate, then pass only the raw JSON text and serializable values to a top-level isolate worker for parsing, indexing, candidate materialization, centroid calculation, and serializable refresh-plan construction. Return the completed refresh plan for one ObjectBox write transaction on the app isolate. Isolate centroid calculation in a dedicated deterministic helper/service and expose injectable MGRS-conversion, transactional-persistence, and diagnostic-logging seams on the app-isolate orchestration layer. Production persistence must execute the plan in one ObjectBox write transaction; tests must be able to make the persistence seam fail after the write phase begins. [L3] [L11]
3. Enforce composite OSM identity in repository/import logic with pre-transaction validation of both source candidates and stored rows. ObjectBox does not need a synthetic remapped OSM key; update behavior must preserve existing ObjectBox IDs. [L2] [L5]
4. Reuse the existing Peak MGRS conversion and Peak-style coordinate editor interaction pattern rather than creating a second coordinate representation, but do not reuse its fixed-`55G` MGRS parsing. Keep `gridZoneDesignator` derived/read-only and use its derived value when parsing Natural Feature MGRS components. Natural Feature refresh must still own source-derived coordinate values for eligible OSM rows. [L5] [L7] [L8]
5. Extend ObjectBox Admin's entity-specific row loading, primary-display resolution, search, save, details-pane, create-state, and confirmed-deletion seams for `NaturalFeature` and `Contact`. The generic admin fallback cannot represent Contact's composed display name or either entity's editable details flow. [L8] [L9] [L10]
6. Generate and verify ObjectBox bindings/model metadata after adding the two entities. Extend the ObjectBox schema guard signature and its test to assert both entities and every required persisted field. Preserve schema compatibility for existing persisted data. [L11]

## Testing Strategy

1. Unit-test the import service using small JSON fixtures and injected file-reader/MGRS-converter/diagnostic-logging seams. Cover direct-node import, fixed-plane closed-way area centroid, fixed-plane open-way line centroid, reversed-segment ring stitching and member-order tie-breaking, multipolygon relations with multiple outer rings and an inner ring, invalid multipolygon roles, touching or crossing inner-ring boundaries with a logged geometry error, zero-area/zero-length geometry, non-polygon relations using direct way members, ignored node and nested-relation members, missing or disconnected geometry, malformed way-node lists and relation-member references, uncounted geometry dependencies, one-required-tag, invalid-OSM-ID, and unsupported-type invalid candidates, Manual-protection precedence over geometry resolution, non-numeric/non-finite/out-of-range coordinates, stored-zone MGRS-only editing, derived non-`55G` grid-zone latitude/longitude editing, MGRS conversion failure, and the fixed source-file unavailable failure. Tests must not read `/Volumes/Services/Features/tasmania_natural_features.json`; include a macOS maintainer-build integration or manual check that the fixed path is readable. [L3] [L11]
2. Cover mapping and normalisation: `alt_name`, duplicate alternate-name validation, water values and fallback, initial Tasmania values, and no county inference. [L4] [L11]
3. Add ObjectBox/repository tests for generated IDs, composite identity matching, duplicate source-candidate and stored-row refresh failures with no writes, initial import, OSM update, Manual protection, the curated-field preservation rules, source omission retention, atomic rollback caused by an injected write-phase persistence failure, deletion followed by source recreation, and permanent Contact deletion. Extend schema-guard coverage to assert both new entities and every required persisted field. [L2] [L5] [L6] [L10] [L11]
4. Add focused Settings widget or robot coverage for tile order, immediate Background job handoff, an existing-running-job refusal, busy state, the exact interrupted-job recovery message, exact success count message, failure feedback, and responsive navigation while the job runs. [L7] [L11]
5. Add ObjectBox Admin widget or robot coverage for Natural Feature editing with read-only identity and grid-zone fields plus Peak-style coordinate/MGRS calculation; verify the absence of an Add Natural Feature button and that all Natural Feature mutations are disabled while its refresh job runs. Cover Contact add validation, edit, composed display/search, and deletion with stable selectors. [L8] [L9] [L10] [L11]
6. Run ObjectBox generation, the ObjectBox schema guard, targeted unit/widget/robot tests, `flutter analyze`, and the full `flutter test` suite. [L11]

## Out of Scope

1. Adding Natural Features to maps, peak markers, Search popup results, Peak Lists, peak correlation, routes, tracks, dashboards, or any other peak-specific feature. [L1]
2. Adding a manual Natural Feature creation flow, a source-suppression/tombstone store, source-file selection or configuration UI, non-macOS support for this maintainer refresh, OS-level background execution, user cancellation, a network OSM refresh, or any geometry lookup beyond the supplied local file. [L3] [L8] [L10]
3. Adding Contact relationships, contact-import/export behavior, communication fields, or contact use in existing Peak, Track, Route, or list workflows. [L9]
