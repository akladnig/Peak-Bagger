# Work Item 02 verification

Date: 2026-10-21. Scope: [Admin live Search and coordinated mutation recovery](work-items/02-admin-live-search-and-mutation-recovery.md). ADS-1.0 with the adopted 2026-10-19 amendment and 2026-10-20/21 supplements; Desktop wide/macOS only.

## Implementation

- Each accepted raw Search edit starts its local committed-record read immediately; Enter also searches. Only matching criteria are trimmed/case-folded. The production repository and mutable fake share the explicit fourteen-entity matching policy, including relationship display names, Waypoint type/MGRS and complete route-graph payload/tag values. Missing values do not turn into searchable placeholders. Existing ID ordering and Schema-only coverage are unchanged; primary-name/title sorting remains a separate alignment gap.
- Selected identity/projection is resolved against committed records before filtering, independently of visible rows. Search, zero matches, read failure and Retry retain the same editor and sole draft. Same-ID refreshed props do not overwrite active Peak/Route/PeakList drafts; Contact/Natural Feature retain their existing protection. Save can retain the same record's details outside the query. Read and selection generations prevent obsolete results/errors or captured selection snapshots from reinstating older context.
- Data Search inherits the shared field theme, displays exactly **Search ⌘F**, has a contextual accessible name and a decorative 24px leading Search icon. There is no trailing submit action, tooltip or extra icon focus stop. Ordinary fields/labels and five-line values remain under their delivered shared owners. Peak coordinates use signed-decimal keyboard affordances, Peak elevation signed-integer, and Route elevations signed-decimal; parsers/ranges/storage precision are unchanged.
- The existing `objectboxAdminSaveProvider` is deliberately extended into one exclusive Save/Delete/recovery lifetime, retaining its established name for forms, router and shell consumers. All six Delete adapters acquire it before confirmation/preparation, through removal, domain follow-up and refresh. Child Cancel/Delete, Escape/Ctrl+C and acknowledgement keep their own local dismissal boundary. Parent input, Search, row/entity/mode/sort, mutations, Cancel/Close, synchronous PopEntry and retained-shell/programmatic departure read the same current gate; rejected actions are not replayed. A visible operation status is shown, and multiple recovery messages scroll within a viewport capped against the actual available height instead of displacing the editor/actions.
- Confirmed storage removal invalidates only that selected identity immediately, before later follow-up. A separate Riverpod Delete coordinator retains only incomplete synchronisation/refresh callbacks, never removal or confirmation. Visible feedback distinguishes **deleted** from incomplete **Synchronisation / Refresh**, with a labelled **Retry**. Successful synchronisation is not replayed if refresh subsequently fails; repeated recovery failure releases protection and retains another Retry. Multiple incomplete outcomes are retained rather than overwriting an earlier recovery.
- Waypoint deletion now delegates through the existing Admin repository to `WaypointsRepository`, removing the screen's direct Store write and exposing a deterministic removal seam. Existing six mutation/relationship/domain boundaries are otherwise retained. No Background Jobs Retry, schema/entity/generated-model change, migration, new loader/editor or broader sorting/navigation redesign was added.
- Cmd+F checks the active routed Data context, current mutation gate, available field, modal/focus route and local-history dropdown/drawer ownership before requesting focus/select-all. It changes no query/identity/draft, mode or route and never defers an unavailable action. The keyboard handler, focus node and existing controllers/listeners are disposed by their presentation owner.

## Native macOS evidence

`test/harness/verify_admin_live_search.dart` is an isolated entry point using the actual Admin screen and controlled repositories, not production startup. It exercises native rendering, keyboard/pointer input, exact supported minimum/larger sizes, light/dark/custom themes, 1×/2× text and draft-preserving resizing. Native rendering/input is separate from deterministic routing/controlled-future tests.

The initial native attempts built successfully but AppleScript did not deliver typing; CoreGraphics delivered ordinary characters but not Command transitions. Instrumented Flutter key events showed `meta=false` throughout, so these modifier probes are **not native Cmd+A/Cmd+F passes**. Trying both targeted/global delivery and modifier-event forms did not establish a native modifier pass. No production shortcut was changed to accommodate injected events, and no system permissions were modified.

The explicitly separated text/render mode is run with:

`flutter run -d macos --dart-define=ADMIN_SEARCH_NATIVE_MODIFIERS=false -t test/harness/verify_admin_live_search.dart`

In that mode only focus/select-all setup is programmatic; native pointer focus and OS-delivered ordinary text, Enter and Backspace drive the actual editor/Search. It checks live exclusion, zero matches, clearing, identity/controller/draft retention, reachable Save and resize/theme/scale rendering. Cmd+F's eligibility/select-all/draft/locking contract is proven by the real-routed deterministic widget tests, **not claimed as native modifier input**. The default modifier-probe mode remains available to reproduce/check host delivery.

Text/render matrix: **pass, 24 configurations**, at **1280 × 960 → 1600 × 1000 → 1280 × 960**, default/custom light/dark and 1×/2× text. The same editor controller/draft and selected identity survive OS typing, exclusion/zero matches, Enter, clearing, resize and theme rebuilds, with reachable Save and no framework errors. The fixture restores its native frame and exits normally (Flutter reports the expected lost device connection after the fixture exits). The existing ObjectBox Swift Package Manager compatibility warning is non-blocking. Native Command-modifier delivery remains unverified on this host; this matrix does not claim a native Cmd+F Pass or attributed human acceptance.

No attributed human visual review or template-parity acceptance is claimed or required by this item. Existing launch/native-window settings and the unrelated inherited Dashboard Time layout gate are unchanged.
